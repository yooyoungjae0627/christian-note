# 성경 주제별 교재 — 빌드 도구

**강의 1개 = 책 1권**(2026-10-09). 책마다 `Theme/NN_이름.pdf` + `.epub`. 도구는 책 번호 NN을 받아 그 이야기 하나만 한 권으로 만든다. 정책: `C:\BibleStudy\docs\policy\성경주제별_교재_제작지침.md`.

## 새 이야기 더하기
1. `원본/NN_짧은이름/` 폴더를 만든다(NN = 02, 03 …).
2. `transcript_raw.txt` — 받은 녹취록 그대로(줄마다 `m:ss` 시각으로 시작).
3. `slides/NN.jpg` — 슬라이드 화면만 잘라 낸 그림(파일 이름 = 슬라이드 번호). 강단 캡처는 투영 스크린만 남긴다.
4. `story.txt` — 다듬은 원고(아래 형식). `01_…/story.txt`를 본보기로.
5. 아래 "빌드"를 그 책 번호로 돌리고, 검사 두 개가 exit 0인지 확인한 뒤 `Theme/`에 저장한다.

## story.txt 형식 (한 줄 = 한 항목, `|` 구분, `#`로 시작하면 주석)
- `@story|번호|제목|부제|유튜브ID|날짜|강사|원 강의 제목`
- `@legend|색 이름|#색코드|뜻` — 이야기 표제 쪽의 「강의 그림의 색깔」
- `@ch|번호|장 제목|부제` — 번호 `0`=시작하며, `end`=마치며
- `@sec|소제목|시각`
- `@p|시작-끝|문단` — 녹취록 줄 시각 범위(양 끝 포함). **녹취록의 모든 줄이 정확히 한 문단에 들어가야** 빌드가 된다(빠짐·겹침 검사)
- `@img|파일|캡션|구절 // 다음 단락|출처` — 슬라이드 + 구절 상자. 구절 칸을 비우면 그림만. `slides/`의 모든 그림이 정확히 한 번 쓰여야 한다
- `@note|용어|설명` — 용어 상자(그 문단 바로 아래)
- `@summary|한 줄` — 한눈에 보는 이야기 12~22줄, `**굵게**`
- `@quiz|질문|답|근거|시각` — 25~41개
- `@faq|질문|답|근거|시각` — 12~14개
- `@gloss|용어|설명` — 용어·인물 풀이에만 싣는 핵심 용어
- 강조: `{1:중요}` `{2:더 중요}` `{3:핵심 명제}`
- `@cover|줄1|줄2` — 표지에 넣는 그 강의의 핵심 문장(원고 문장 그대로). 표지 그림은 이야기 폴더의 `cover.svg`(viewBox 0 0 200 200, width/height 없이). 둘 다 없으면 빌드가 멈춘다. 미리보기 `node cover_preview.mjs <원본> NN out.png`
- `@storynote|글` — 표제 쪽 안내문(예: 영상 링크를 받지 않은 강의라 영상 이동이 없음, 그림은 정리한 사람이 만듦)
- `@verse|머리|구절 // 다음 단락|출처|읽음 또는 언급` — 그림 없는 말씀 상자. 강의에서 읽은 본문은 `읽음`, 장절만 말한 것은 `언급`. 슬라이드가 없는 강의는 **표준킹제임스성경 본문을 글자 그대로**(저장소 공통 도구 `node ../../../tools/kjv.mjs "마가복음 15:37-41"`), 출처 끝에 `· 표준킹제임스성경`(2026-10-10, README §3)
- `@img|NN.jpg|캡션|구절|출처|made` — 다섯째 칸 `made` = 정리한 사람이 만든 그림. `figs/NN.html`(fig.css 클래스로 짠 1400×700 슬라이드 조각)을 `node figs.mjs <원본>`이 `slides/NN.jpg`로 찍는다
- 유튜브ID 칸 `-` = 링크를 받지 않은 강의 → QR·▶·영상 링크를 하나도 넣지 않는다

## (폐기 2026-10-09) 통합 이야기 — 강의별 한 권 원칙으로 더는 만들지 않는다. 옛 원고를 읽을 수 있게 도구 기능만 남겨 둔다
- 녹취록: 첫 강의 `transcript_raw.txt`, 둘째 `transcript_raw_2.txt`, 셋째 `_3` …
- 원 강의 제목: `@lecture|제목`을 강의 순서대로 적는다(표제 쪽에 「원 강의 1·2」로 나옴). `@story`의 원 강의 칸은 `-`
- 둘째 강의부터 시각 앞에 강의 번호: `@p|2/12:34-2/13:10|…`, `@sec|소제목|2/12:34`, `@quiz|…|2/12:34`. 한 문단은 한 강의 안에서만
- 시각 순서 검사는 강의마다 따로 → 두 강의 문단을 주제 흐름에 맞춰 장·소제목 안에 엮어도 된다(각 강의 안의 순서는 지킨다)
- 통합 이야기에는 유튜브ID를 둘 수 없다(강의마다 영상이 다름)

## 빌드 (이 PC: Python 없음 → Node + Edge 명령줄 인쇄)
OneDrive 안에 node_modules를 두지 않는다. 임시 작업 폴더에서:
```
mkdir %TEMP%\topicbook && cd %TEMP%\topicbook && npm init -y && npm i sharp qrcode mupdf jsqr pngjs jszip fast-xml-parser
copy "<원본>\tools\*" .
node figs.mjs      "<원본>" NN        (만든 그림이 있으면: figs/*.html → slides/*.jpg)
node fit.mjs       "<원본>" out NN     (그림 위치 맞춤 → 이야기 폴더의 layout.json)
node build_pdf.mjs "<원본>" out NN  && node verify_pdf.mjs  "<원본>" out\NN_이름.pdf NN
node build_epub.mjs "<원본>" out NN && node verify_epub.mjs "<원본>" out\NN_이름.epub NN
node audit.mjs out\NN_이름.pdf out\toc_pages.json   (남은 공란 보고)
```
- 책 번호 없이 돌리면 멈춘다(강의를 한 권에 묶지 않도록). 여러 권은 책마다 위 순서를 돌린다.
- Edge는 Claude Code 샌드박스 안에서 바로 종료되므로 **샌드박스 밖에서** 실행한다.
- 차례 쪽 번호: 제목마다 보이지 않는 표식(@@id@@)을 넣어 찍고, 표식이 나온 쪽을 읽어 다시 찍는다(값이 안 바뀔 때까지).
- **Edge 이동점 버그**: Chromium은 PDF 이동점 높이를 쪽 위 여백(16mm)만큼 덜 내려 적는다. `build_pdf.mjs`의 `fixDests`가 바로잡는다. 이게 없으면 「목차로 이동」을 눌렀을 때 차례 항목이 화면 맨 위가 아니라 16mm 아래에 온다.
- verify_pdf: 모든 QR 300dpi 판독, 영상ID, 빠진 영상 링크, 차례 쪽 번호, 「목차로 이동」 도착 높이(차례 항목 막대 바로 위 0~6pt)·단추 위치(왼쪽 아래), 본문 그림 수 = 슬라이드 수.
- verify_epub: mimetype, XML 문법, 내부 이동·그림 연결, 영상 링크, 원고와 문단·그림·구절 상자·용어 상자·문제·답안·예상 질문·강조 수 일치, 「목차로 이동」, mupdf로 열림.

## 만든 그림·원고 검사 (2026-10-04 추가)
- `node check_story.mjs <이야기폴더>` — 이야기 하나의 원고 검사(그림은 figs/NN.html만 있어도 됨).
- `node figs.mjs <원본> [02 05 …]` — 만든 그림 찍기. 그림마다 글 폭·높이를 재서 1240×588(위 칩 .title 있으면 높이 540, 아래 출처 .src 있으면 568)을 넘으면 내용 전체를 zoom으로 줄여 넣는다. 끝에 「넘쳐서 줄인 그림」 목록. `FORCE=1`이면 전부 다시 찍는다.
- 구절 찾기는 저장소 공통 `tools/kjv.mjs`(표준킹제임스성경, 2026-10-10). 옛 `kjv.mjs`(hangl.net 한글KJV)는 지웠다.
