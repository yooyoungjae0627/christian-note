# 성경 구절 테스트 카드 제작 정책

첫열매들 주간 구절 테스트용 HTML 카드를 만들 때 지켜야 할 규칙. 밀크 5·6·7 카드를 만들며 확정된 내용이다.

## 1. 대원칙 — 본문은 토씨 하나 바꾸지 않는다

가장 중요한 규칙이다. 영재가 올려준 구절 테스트 범위가 유일한 기준이다.

- 올려준 본문을 그대로 복사한다. 단어 하나, 조사 하나, 문장부호 하나 바꾸지 않는다.
- 올려준 본문에 ... 생략 부호가 있으면 그 생략 부호까지 그대로 둔다. 생략된 부분을 임의로 채워 넣지 않는다.
- 줄바꿈 위치도 올려준 그대로 유지한다.
- 다른 역본으로 바꾸지 않는다. 강의 슬라이드에 다른 문구로 적혀 있어도, 기준은 올려준 본문이다.
- 구절을 추가하지 않는다. 범위에 없는 절은 넣지 않는다. 문맥상 필요해 보여도 넣지 않는다.
- 요약·축약·재구성 금지. 길어도 그대로 간다.

실제로 이 규칙을 어겼다가 전체를 다시 만든 적이 있다. 슬라이드 문구를 가져오고, 범위 밖 절을 넣고, 긴 구절을 잘라냈던 경우다. 재구성하려는 유혹이 생기면 멈추고 올려준 원문을 다시 본다.

### 본문 보존을 보장하는 구조

본문(t)은 절대 가공하지 않는다. 형광펜·색칠은 별도 배열(hl)에 "본문 안에 실제로 존재하는 부분 문자열"로만 적고, 화면에 그릴 때 찾아서 감싼다.

```js
{cat:"제사의 기쁨", b:"느헤미야", c:12,
 hl:[["n","예루살렘의 즐거움의 소리가 심지어 멀리 떨어진 곳까지 들렸더라"]],
 t:`또한 그날 그들은 엄청난 희생 제물들을 바쳤고 크게 기뻐하였더라. ...`},
```

빌드 후 반드시 검증 스크립트를 돌린다: 모든 hl 문자열이 해당 t 안에 실제로 존재하는지 확인. 하나라도 없으면 본문을 건드렸다는 뜻이다.

## 2. 소제목(카테고리)

- 각 구절 위에 소제목을 단다.
- 출처는 강의 슬라이드 제목 → 노션 강의 페이지 → 프로젝트 교리 문서 순. 셋 다 없으면 지어내지 말고 영재에게 슬라이드를 요청한다.
- 슬라이드 제목이 있으면 그 제목을 그대로 쓴다. 같은 제목이 여러 문항에 걸쳐 있으면 중복해서 그대로 단다.
- 제목이 없는 슬라이드(좌우 대비형 등)는 중립적인 쌍 표기로 묶는다. 예: 제사장의 꿈 ① / 신부의 꿈 ①.
- 교재에 "강의 슬라이드에서"로만 실리고 제목이 없는 슬라이드는, 교리 문서(`docs/doctrine/milkNN.md`) 장별 요지에 **그 구절이 명시된 장의 제목**을 쓴다. 장 안에 구절이 명시되지 않았으면 쓰지 않는다.
- 슬라이드 제목에 책 이름이 들어 있으면(예: "에스겔 성전 = 셋째 하늘 성전") 책 이름이 든 부분만 빼고 나머지를 그대로 쓴다(→ "셋째 하늘 성전"). 단어를 새로 지어 넣지 않는다.
- 한 문항이 두 슬라이드에 걸치면 두 제목을 " · "로 잇는다(예: 마지막 전쟁 · 백보좌 심판).
- 어디에도 근거가 없는 문항은 cat을 빈 문자열로 둔다 → 화면에 "카테고리 미확인 (슬라이드 주시면 반영)"이 뜬다. 범위 순서로 장을 짐작해 붙이지 않는다(17회차에서 그렇게 했다가 재구성함).

### 힌트 금지 (중요)

소제목에 정답을 좁히는 단어가 들어가면 안 된다.

넣으면 안 되는 것:
- 성경 책 이름 (창세기, 마태복음, 바울서신 …)
- 장 번호, 숫자 전반
- 책 묶음을 특정하는 표현 — 바울 / 13통 / 53권 / 할례자·무할례자 복음 등

빌드할 때 책 이름 사전과 숫자 정규식으로 자동 검사한다.

## 3. 색칠·형광펜

- 연두색 형광펜(hl-n): 모든 구절에 하나 이상. 그 구절의 핵심 어구에 칠한다. 외울 때 눈이 거기 꽂히게 하는 용도.
- 노랑 형광펜(hl-y / hl-k): 노션 강의 페이지에 밑줄·배경색이 쳐진 부분을 그대로 옮길 때 쓴다.
- 글자색(hl-r, hl-o, hl-b, hl-g, hl-p, hl-w): 강의 슬라이드의 글자 색을 재현할 때 쓴다.
- 퀴즈 모드에서는 연두색만 보여준다. 나머지 색은 아래 전체 목록에서만 나온다.

## 3-1. 시대·복음 테마 표시 (18회차부터, 사용자 지시 2026-10-09)

각 구절이 밀크 자료에서 **어떤 시대·복음 구분으로 쓰였는지** 분석해 소제목 아래에 테마 칩(글자 배경색)으로 적는다.

- 분석 대상: `source_text/*.txt`(밀크 1~10강 교재 글자) + `docs/doctrine/milkNN.md` 장별 요지. 구절 참조를 찾아 그 구절이 놓인 슬라이드 제목과 장 요지를 본다.
- 색과 이름은 밀크 교재 '이 책을 읽는 법'의 그림 색 구분(`docs/doctrine/milk07.md` 핵심 도식 11)을 따른다. 새 이름을 지어내지 않는다.

| 키 | 칩 글자 | 색 |
|---|---|---|
| jew | 유대인의 시대 · 제사장 | 아이보리·노랑 바탕 |
| gen | 이방인의 시대 · 신부 | 주황 바탕 |
| mil | 천년왕국 | 파랑 바탕 |
| nhe | 새 하늘 새 땅 | 주황 테두리 |

- 한 구절이 두 구분에 걸치면 칩을 둘 단다(예: 새 예루살렘 신부 → 이방인의 시대·신부 + 새 하늘 새 땅).
- 자료가 어느 구분에도 놓지 않은 구절(예: 두 가지 표현 방법 — 하나님의 시점 설명)은 `th:[]`로 비운다. 짐작으로 칠하지 않는다.
- **다른 강의 사용처**: 같은 구절이 다른 밀크 강의 슬라이드에도 쓰였으면 `u:["밀크 N강 · 슬라이드 제목"]`으로 적는다. 화면에는 "다른 강의: …"로 작게 나온다. 슬라이드 제목이 없는 곳(근거·답안)은 적지 않는다.
- 힌트 금지는 칩·사용처에도 그대로 적용한다: 책 이름, 바울/13통/53권/할례자 표현이 든 슬라이드 제목은 빼고 적는다. 강 번호·'7년' 같은 숫자는 장 번호 힌트가 아니므로 사용처에서는 허용한다(소제목은 여전히 숫자 금지).
- 데이터: 문항마다 `{th:["jew"], u:[...], cat:..., b:..., c:..., hl:..., t:...}`. logic.part의 `THEMES`가 칩을 그린다. th·u가 없는 옛 회차는 아무것도 그리지 않는다(하위 호환).
- 빌드 후 검증에 추가: u 문자열에 책 이름·금지 표현이 없는지 검사.

## 4. 화면 구성

### 상단 — 퀴즈 모드
- 한 번에 한 문제. 구절을 보여주고 아래에 책 이름 + 장을 입력한다.
- 엔터 또는 옆의 확인 버튼으로 채점.
- 정답 → 0.8초 뒤 아직 못 맞힌 다음 문제로 넘어간다.
- 오답 → 넘어가지 않는다. 같은 문제에 머물고, 입력창이 자동 선택되어 바로 다시 칠 수 있다. 오답 횟수는 세지 않는다.
- 모르겠으면 정답 보기, 넘기려면 건너뛰기 →.
- 전 문항을 맞히면 완료 화면 + 처음부터 다시 풀기.

### 하단 — 전체 구절 목록
- 모든 구절을 번호와 함께 나열. 각 카드마다 입력창 · 확인 · 정답 버튼.
- 퀴즈에서 푼 결과가 해당 카드에 그대로 반영된다.

### 카드 맨 위 — 강의 영상 링크 (17회차부터)
- 각 카드 최상단(소제목 위)에 "▶ 강의 영상 MM:SS부터" 링크를 단다. 퀴즈·목록 둘 다.
- 데이터: orig{N}.js 맨 위에 `const VIDEO = "<유튜브 URL>";`, 문항마다 `v:"MM:SS"` 또는 `v:"H:MM:SS"`. 링크는 `VIDEO&t=<초>s`.
- 시각은 영재가 준 스크립트에서 고른다. 스크립트에는 구절 낭독이 빠져 시간 공백으로 남으므로, **그 공백 바로 앞 줄의 시각**을 쓴다(낭독 몇 초 전부터 재생). 공백이 어느 구절인지 불분명하면 해당 장(소단락) 시작 시각을 쓰고 보고한다.
- v가 없는 데이터(이전 회차)는 링크를 그리지 않는다 — logic.part 공용 변경이지만 하위 호환.

### 맨 아래 고정 바
전체 초기화 · 문제 섞기 · 전체 정답 보기 · 전체 채점

## 5. 정답 판정

정답은 책 이름 + 장까지만. 절은 묻지 않는다.

입력은 넉넉하게 받아들인다:

| 받아들이는 형태 | 예 |
|---|---|
| 정식 이름 | 마태복음 17 |
| 줄임말 | 마태 17, 마 17, 마17 |
| 한 글자 약어 | 행 5, 살전4, 벧전 2 |
| 장 표기 | 마태복음 17장 |
| 절까지 쓴 경우 | 마태복음 17:20 (장만 보고 판정) |
| 공백 없음 | 마태복음17 |

약어 사전은 66권 전체를 커버한다. 새 책이 범위에 들어오면 사전에 추가됐는지 먼저 확인한다.

## 6. 빌드와 납품

### 파일 구조

세 조각을 이어 붙여 단일 HTML 파일을 만든다.

```
cat head{N}.part orig{N}.js logic.part > verse-cards-milk{N}.html
```

- head{N}.part — 제목, 회차, 문항 수, CSS
- orig{N}.js — 구절 데이터 (const DATA = [...])
- logic.part — 공통 로직 (약어 사전, 채점, 퀴즈, 목록). 모든 회차가 공유하므로 여기를 고치면 전 회차에 반영된다.

### 빌드 후 필수 검증
- hl 문자열이 전부 t 안에 존재하는가
- 소제목에 책 이름·숫자가 섞여 있지 않은가
- 문항 수가 head 파일의 표기(#total, #qTotal, 하단 문구)와 일치하는가
- 브라우저에서 띄워 JS 에러 0건, 카드 수 일치 확인

### 납품
항상 두 가지를 같이 준다.
- 아티팩트로 퍼블리시 (회차별 URL 유지 — 수정할 때는 같은 URL에 재발행)
- SendUserFile로 HTML 파일 전달 (아티팩트가 안 열릴 때 대비)

## 7. 문항 추가·삭제 요청 처리

영재는 문항을 하나씩 빼면서 범위를 좁혀 간다. 이때 지킬 것:

- 지정한 것만 지운다. "베드로전서 1장 빼줘"에 베드로전서 2장까지 같이 지우면 안 되고, 그 반대도 안 된다.
- 같은 책·장이 여러 문항이면 몇 개인지 확인하고 지운다. "열왕기상 8장 2개" → 2개 다 삭제. 특정 하나만이면 구별되는 구절 내용으로 집어서 지운다.
- 키워드로 필터링해서 지울 때는 다른 구절이 같이 걸리지 않는지 확인한다. (예: "수송아지"로 필터링했다가 "수송아지의 피로 행한 것과 같이"가 들어간 다른 구절까지 지워진 적 있음 — 삭제 전후 개수를 반드시 세어 본다.)
- 지운 뒤 남은 개수가 요청한 숫자와 맞는지 확인하고, head 파일의 문항 수 표기도 같이 고친다.
- 삭제 후 첫 문항이 바뀌면 그 사실을 알려 준다.
