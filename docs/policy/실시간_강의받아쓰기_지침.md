# 실시간 강의 받아쓰기 지침

> 첫열매들 예배 강의를 **듣는 동안** 갤럭시 탭의 받아쓰기 글을 받아 원고 초안을 쌓고, 강의가 끝나면 책(PDF + EPUB)으로 만드는 절차. (사용자 지시 2026-10-31 신설 「새 세션을 틀어도 자동으로 하게 명령어를 심어 줘」)
> 책 내용·모양 규칙은 이 문서에 다시 적지 않는다 — **`성경주제별_교재_제작지침.md`**(+ 밀크 ①)와 **README §3**이 원본이다. 이 문서는 "언제·무엇을·어떤 순서로"만 정한다.

## 0. 명령어 세 개

| 사용자가 이렇게 말하면 | Claude가 하는 일 (묻지 않고 끝까지) |
|---|---|
| **「받아쓰기 시작」** (+ 강의 제목, 없으면 「제목 미정」) | §2 시작 |
| **「받아쓰기 반영」** (또는 채팅에 받아쓴 글을 붙여 넣음) | §3 한 회 반영 — 반복 실행은 이 명령이 10분마다 저절로 돈다 |
| **「받아쓰기 끝」** | §4 마무리 — 반복을 멈추고 책까지 만든다 |

- 슬래시 명령 `/live-lecture 시작|반영|끝`도 같은 뜻이다(`.claude/skills/live-lecture/`).
- 시리즈는 별다른 말이 없으면 **Theme(성경 주제별 교재)**. 사용자가 다른 시리즈를 말하면 그 시리즈 지침을 따른다.

## 1. 받아쓰기 글이 들어오는 길
1. **Google Drive 폴더 「강의 받아쓰기」** — 탭의 삼성 「음성 녹음」에서 녹음 → 「텍스트 변환」 → 「공유」 → 텍스트(.txt)로 이 폴더에 저장. Claude는 Google Drive 연결(connector)로 이 폴더의 새 파일을 읽는다. 연결이 없는 환경(예: Windows 기기의 Claude Code)이면 2번 길만 쓴다.
2. **채팅 붙여 넣기** — 받아쓰기 앱(음성자막변환·삼성 음성 녹음 등)의 글을 복사해 채팅에 붙여 넣는다.
- 앞 조각과 겹쳐서 와도 된다. 겹친 줄은 Claude가 한 번만 남긴다.
- 삼성 음성 녹음은 한 번에 변환되는 길이에 제한이 있을 수 있다 — **10~15분마다 끊어 녹음**한다. **정지 → 새 녹음 시작은 1~2초 안에**(사용자 지시 2026-10-31 「텀이 진짜 빨라야 한다」): 정지를 누르면 저장 이름 창이 떠도 무시하고 곧바로 녹음 단추를 누른다. 변환·공유는 새 녹음이 돌아가는 동안 한다. 강사가 말을 잠깐 멈출 때 끊는다.
- 끊긴 사이에 말이 빠졌으면(앞 조각 끝과 다음 조각 처음이 이어지지 않으면) Claude는 지어서 잇지 않고 `transcript_raw.txt`와 `story.txt`에 `[끊김 — 몇 초 빠짐]`을 남긴다. 「받아쓰기 끝」에서 영상·스크립트를 받으면 그것으로 채운다.
- 끊김을 아예 없애려면 **음성자막변환 앱(끊지 않고 계속 받아씀)**으로 실시간 글을 붙여 넣고, 삼성 음성 녹음은 통째로 한 번만 녹음해 강의 뒤에 변환해 대조한다(두 앱이 마이크를 같이 쓸 수 있는지는 기기에서 먼저 시험).

## 2. 「받아쓰기 시작」
1. 이 지침, README §3, 시리즈 지침을 읽는다.
2. 다음 번호 NN으로 `첫열매들 강의 정리/원본/NN_이름/`을 만든다(제목 미정이면 `NN_받아쓰기_YYYYMMDD`, 제목을 받으면 폴더 이름을 바꾼다). 넣는 파일:
   - `transcript_raw.txt` — 받아쓴 글을 **들어온 그대로** 쌓는다(빈 파일로 시작).
   - `story.txt` — 원고 초안. 맨 위에 `# 받아쓰기 진행 중 — 초안` 주석.
   - `받아쓰기_상태.md` — 시작 시각, 반영한 Drive 파일 ID·이름 목록, 마지막으로 반영한 줄, 회차별 기록.
3. Drive 연결이 있으면 「강의 받아쓰기」 폴더를 찾는다. 없으면 만들거나 사용자에게 만들어 달라고 한 줄로 말한다.
4. **반복 실행을 건다:** `loop` 스킬로 `10m 받아쓰기 반영`. 반복 기능이 없는 환경이면 사용자가 「받아쓰기 반영」을 말할 때마다 한 회씩 한다.
5. 커밋·푸시(`draft: NN 받아쓰기 시작`)하고, 사용자에게 할 일(녹음 → 변환 → 공유)을 세 줄로 알려 준다.

## 3. 「받아쓰기 반영」 한 회
1. `받아쓰기_상태.md`를 읽어 어디까지 반영했는지 확인한다.
2. Drive 폴더에서 시작 시각 뒤에 생긴 **아직 반영하지 않은 파일**을 만든 순서대로 읽는다 + 그 사이 채팅에 붙여 넣은 글.
3. `transcript_raw.txt` 끝에 덧붙인다. **받아쓴 글은 고치지 않는다**(오인식도 그대로). 앞 조각과 겹친 줄만 뺀다.
4. `story.txt` 초안을 이어 쓴다 — 시리즈 지침 §3(내용)대로, 강의에 나온 것만. 단 강의 중에는:
   - **성경 구절 본문을 넣지 않는다.** `〔구절 확인: 책 장:절〕` 자리 표시만 남긴다(받아쓴 구절은 토씨가 틀린다).
   - 사람 이름·교리 용어·숫자가 의심스러우면 짐작으로 고치지 않고 `[확인 필요: 받아쓴 글자]`.
   - 슬라이드 자리는 `〔슬라이드 자리〕`.
5. 새 글이 없으면 아무것도 바꾸지 않고 "새 글 없음" 한 줄만 보고한다(빈 커밋 금지).
6. 새 글이 있으면 커밋·푸시(`draft: NN 받아쓰기 반영 (+N줄, 누계 M줄)`)하고 한 줄 보고.
7. **이 단계에서는 빌드하지 않는다**(PDF·EPUB 빌드는 몇 분씩 걸린다).

## 4. 「받아쓰기 끝」
1. 반복 실행을 멈추고, 마지막으로 §3을 한 번 더 돈다.
2. 사용자에게 한 번에 요청한다: 강의 제목(미정이었으면), 날짜, **슬라이드 사진**, 유튜브 링크(있으면), `[확인 필요]` 목록 답.
   - 슬라이드를 안 주면 시리즈 지침 §0대로 정리한 사람이 그림을 디자인한다. 링크를 안 주면 영상 이동 없음.
3. 받은 것으로 원고를 마무리한다: 자리 표시 구절을 슬라이드 글자 또는 `node tools/kjv.mjs`(표준킹제임스성경) 글자 그대로 채우고, `[확인 필요]`·`〔…〕`가 하나도 안 남게 한다. 초안 주석을 지운다.
4. **「메모리 뱅크 업데이트」 네 단계를 그대로 한다**(README §3): ① `transcript_raw.txt`를 `memory-bank/첫열매들_강의스크립트/1_일반예배/`에 다음 번호 md로(머리에 「실시간 받아쓰기(삼성 음성 녹음 등) — 오인식 그대로, 시각 링크 없음」) 넣고 목록 README 갱신 → ② 커밋·푸시 → ③ 시리즈 지침대로 책(PDF + EPUB) 빌드·검사(check_story, verify_pdf, verify_epub, audit) → ④ 커밋·푸시.
5. 검사 exit code와 수치를 보고한다. 이 환경에서 빌드 도구(Edge 인쇄 등)가 돌지 않으면 "원고까지 완료, 빌드는 Windows 기기에서" 라고 사실대로 보고하고 완료라고 하지 않는다.
6. `받아쓰기_상태.md`는 지우고, 진행 기록은 `memory-bank/journal/`에 남긴다.
