# 줌 녹화 교재 지침

> 줌(Zoom)으로 송출된 첫열매들 강의(약 1시간 30분)를 **녹화 영상으로** 받아, 받아쓰기·슬라이드 추출을 거쳐 성경 주제별 교재 한 권(PDF + EPUB)으로 만드는 절차. (사용자 지시 2026-11-01 신설)
> 책 내용·모양 규칙은 이 문서에 다시 적지 않는다 — **`성경주제별_교재_제작지침.md`**(+ 밀크 ①)와 **README §3**이 원본이다. 이 문서는 줌 녹화에서만 다른 점과 순서를 정한다.

## 0. 명령어
| 사용자가 이렇게 말하면 | Claude가 하는 일 (묻지 않고 끝까지) |
|---|---|
| **「최근 줌 녹화 교재 집필해줘」**, 「줌 녹화 교재 집필」, 「줌 녹화 책」 (+ 강의 제목·날짜, 파일 위치는 있으면) | §1-2 → §3 ~ §5 전부. 강의 제목·날짜를 안 주면 녹화 폴더 이름·자막·첫 슬라이드에서 찾고, 그래도 없으면 그것만 묻는다 |

- 슬래시 명령 `/zoom-book`도 같은 뜻이다(`.claude/skills/zoom-book/`).
- **어느 기기·세션이든** 저장소를 pull 받은 곳이면 이 명령 하나로 된다(사용자 지시 2026-11-01 「어디서든 깃허브 크리스찬 노트를 풀 받으면 연동해서」). 시작할 때 `git pull`로 최신 지침을 받는다.
- 파일 위치를 말하지 않으면 **가장 최근 녹화**를 쓴다(§1-2).
- 시리즈는 별다른 말이 없으면 **Theme(성경 주제별 교재)**.

## 1. 줌 녹화에서만 다른 규칙 (사용자 지시 2026-11-01)
- **영상 이동을 하지 않는다.** 줌 녹화로 만든 책에는 QR·▶ 시각·영상 링크를 하나도 넣지 않는다(`@story`의 유튜브ID 칸 `-`). 스크립트에는 분:초만 적는다. 표제 쪽 안내문(`@storynote`)에 "줌 녹화 영상으로 만든 책이라 영상 구간 이동이 없다"고 적는다.
- **강사 얼굴·모습, 참가자 화면(갤러리), 교회 전경이 보이는 화면은 AI 칠판 이미지로 바꾼다**(주제별 지침 §0과 같음). 칠판의 글자·구절은 원래 화면 글자 그대로.
- **녹화 허락은 받았다**(사용자 확인 2026-11-01). 다른 강의도 사용자가 허락받은 녹화만 쓴다.

## 1-1. 클라우드 세션 준비
- 세션을 열면 먼저 `bash tools/cloud_setup.sh`(한글 글꼴·빌드 의존성·받아쓰기 엔진, 1~2분, 끝나면 `/tmp/topicbook/.ready`).
- 클라우드 세션에서도 책 빌드가 된다: `/tmp/topicbook`에 `첫열매들 강의 정리/원본/tools/*`를 복사해 지침의 빌드 순서대로 돌린다(Edge 대신 headless Chromium). 2026-11-01 36권으로 시험: Windows 완성본과 같은 91쪽, verify_pdf·verify_epub exit 0, 공란 쪽 목록 1%p 안에서 같음.

## 1-2. 가장 최근 녹화 찾기·준비 — `node tools/zoom/zoombook.mjs`
- 한 번에: 가장 최근 녹화 찾기 → 슬라이드 후보 프레임 → 음성 → 받아쓰기 → `transcript_raw.txt`. 결과는 저장소 밖 `<임시폴더>/zoombook/<녹화 이름>/`(info.json에 찾은 파일·받아쓰기 방법·줄 수·프레임 수).
- **기본 조합(사용자 지시 2026-11-01): 줌 녹화 영상 = 슬라이드, 삼성 음성 녹음 「텍스트 변환」 글(.txt, 시각 포함) = 말씀.** 클라우드 받아쓰기 모델(huggingface.co)이 없어도 된다.
  - 삼성 변환이 끊겨 .txt가 여러 개면 **파일 이름 순서**(음성 001, 002 …)로 시간을 이어 붙인다. 같은 이름의 음성 파일(.m4a)도 있으면 그 길이로, 없으면 앞 파일 마지막 시각 + 5초로 다음 파일 시작을 정한다(info.json `method.parts`에 기록).
  - 영상이 없으면 같은 곳의 **슬라이드 캡처(.jpg/.png)**를 슬라이드 후보로 쓴다. 영상도 캡처도 없으면 슬라이드를 사용자에게 요청한다(지어내지 않음).
  - 한 폴더에서 가장 최근 파일 기준 24시간 안의 파일만 한 강의로 묶는다.
- 찾는 곳: `ZOOM_DIR` → PC 줌 로컬 녹화 기본 위치(`~/Documents/Zoom`, `~/OneDrive/문서/Zoom`, `~/OneDrive/Documents/Zoom`) → **채팅 첨부(`/mnt/user-data/uploads`)** → `/tmp/zoom_in`(클라우드). 경로를 인자로 주면 그것. `--find`는 찾기만.
- **클라우드 세션:** 먼저 `bash tools/cloud_setup.sh`.
  - **영상은 채팅에 첨부**해서 받는다(첨부 파일은 `/mnt/user-data/uploads`에 생긴다). Google Drive 연결은 파일을 대화 안으로 통째로 옮기는 방식이라 **글·사진 같은 작은 파일만** 받을 수 있고 1~2GB 영상은 받지 못한다(2026-11-01 확인). drive.google.com 직접 접속도 막혀 있다.
  - 삼성 .txt·슬라이드 캡처는 채팅 첨부 또는 Google Drive 「줌 녹화」 폴더(2026-11-01 만듦). Drive에서 받은 것은 `/tmp/zoom_in/<날짜>/`에 저장하고, 영상이 첨부에 있으면 같은 폴더로 모아(복사) 그 폴더를 인자로 실행한다.
- **Windows PC:** 줌 로컬 녹화가 끝나 변환되면 바로 실행된다. ffmpeg가 없으면 `ffmpeg-static`, 파이썬이 없으면 Node 받아쓰기(transformers.js)를 저장소 밖 임시폴더에 알아서 설치한다(처음 한 번).
- 받아쓰기 순서: 줌 자막(.vtt) → **같은 폴더의 받아쓴 글(.txt, 삼성 음성 녹음 「텍스트 변환」 등, 시각 포함)** → 파이썬 faster-whisper(`transcribe.py`) → Node transformers.js(`transcribe.mjs`).
- **받아쓰기 모델 없이 하는 길(클라우드 네트워크 설정을 안 바꿨을 때)**(사용자 지시 2026-11-01): 강의 중 탭의 삼성 음성 녹음으로 녹음 → 끝나면 「텍스트 변환」 → 시각이 함께 나오게 텍스트(.txt)로 공유 → 줌 녹화 영상과 **같은 Drive 「줌 녹화」 폴더**에 올린다. Claude는 둘을 `/tmp/zoom_in/<녹화 이름>/` 한 폴더에 받아 실행한다. 녹음을 시작한 시각이 영상과 다르면 분:초가 영상과 어긋날 수 있다(책에는 영상 이동이 없으므로 순서만 맞으면 된다). 다 안 되면 exit 3으로 멈춘다 — 지어서 채우지 않고 사용자에게 알린다.
- exit 코드: 0 준비 완료, 2 녹화 없음, 3 받아쓰기 불가, 4 줌 변환 전(.zoom 파일), 5·6 ffmpeg 문제.

## 2. 녹화 받기
- 좋은 순서: ① 호스트 **클라우드 녹화 + 오디오 자막**(.vtt가 함께 나옴 → 받아쓰기 단계 생략) ② PC 줌 **로컬 녹화**(mp4 + 음성 m4a) ③ 갤럭시 탭 **화면 녹화**(삼성 화면 녹화, 소리 = 미디어 소리).
- 녹화 보기는 **화면 공유(슬라이드)가 크게** 나오는 보기로. 갤러리 보기는 쓰지 않는다.
- 클라우드 세션은 영상을 채팅에 첨부, 삼성 글·캡처는 첨부 또는 Google Drive 「줌 녹화」 폴더(§1-2). Windows 기기에서 작업하면 줌 녹화 폴더나 저장소 밖 임시 폴더에 둔다. **녹화 영상·음성 파일은 커밋하지 않는다.**

## 3. 받아쓰기 → `transcript_raw.txt`
1. 다음 번호 NN으로 `첫열매들 강의 정리/원본/NN_이름/`을 만들고, §1-2가 만든 `transcript_raw.txt`를 복사한다. (아래 2·3은 손으로 할 때)
2. 줌 자막(.vtt)이 있으면: `node tools/zoom/vtt2raw.mjs 자막.vtt > transcript_raw.txt`.
3. 없으면: `node tools/zoom/frames.mjs 녹화.mp4 <임시폴더> --audio`로 `audio.wav`를 만들고 `python3 tools/zoom/transcribe.py <임시폴더>/audio.wav 받아쓰기.srt`(faster-whisper, 한국어, 기본 모델 medium)로 받아쓴 뒤 같은 `vtt2raw.mjs`로 바꾼다.
   - 클라우드 세션은 모델 내려받기 주소(`huggingface.co`)가 환경 네트워크 설정에서 허용돼야 한다. 막혀 있으면 사용자에게 그 주소를 허용해 달라고 하거나 Windows 기기에서 받아쓴다 — 받아쓰기 없이 지어서 채우지 않는다.
4. `transcript_raw.txt`의 글은 고치지 않는다(오인식 그대로). 고치는 것은 원고(story.txt) 단계에서, 시리즈 지침 §3대로 고치고 보고한다.

## 4. 슬라이드 → `slides/NN.jpg`
1. §1-2가 만든 `frames/`(손으로는 `node tools/zoom/frames.mjs 녹화.mp4 <임시폴더>`) — 화면이 바뀌는 곳마다 원본 해상도 프레임과 `frames.tsv`(시각). 너무 많거나 적으면 문턱(셋째 인자, 기본 0.12)을 바꿔 다시.
2. 프레임을 보고 같은 슬라이드는 한 번만, **화면 공유 부분만** 잘라 `slides/NN.jpg`(슬라이드 번호 순)로 쓴다.
3. 얼굴·참가자·교회 전경이 보이는 프레임은 §1대로 AI 칠판 이미지로 바꾼다.
4. 임시폴더의 프레임은 커밋하지 않는다.

## 5. 원고 → 책 → 메모리 뱅크
1. `story.txt`·`cover.svg`를 시리즈 지침대로 쓴다. 구절은 슬라이드 글자 그대로, 슬라이드에 없으면 `node tools/kjv.mjs`(표준킹제임스성경).
2. **「메모리 뱅크 업데이트」 네 단계를 그대로 한다**(README §3): ① `transcript_raw.txt`를 `memory-bank/첫열매들_강의스크립트/1_일반예배/` 다음 번호 md로(머리에 「줌 녹화 받아쓰기 — 오인식 그대로, 분:초만, 영상 링크 없음」) 넣고 목록 갱신 → ② 커밋·푸시 → ③ 책 빌드·검사(check_story, fit, build_pdf, verify_pdf, build_epub, verify_epub, audit) → ④ 커밋·푸시.
3. 검사 exit code와 수치를 보고한다. 빌드 도구가 돌지 않으면 "원고까지 완료, 빌드는 Windows 기기에서"라고 사실대로 보고하고 완료라고 하지 않는다.
