# 2026-11-11 성경 해석 챗봇 — `chatbot/` (웹 채팅 화면, 개인 Claude Code로 답)

다음 세션이 이어서 할 수 있게 남기는 기록. 사용 설명은 `chatbot/README.md`.

## 사용자가 정한 것 (순서대로)
1. 「교회 정책을 LLM화해서 챗봇을 개발하고 싶다」 — 대상은 **교회 성도들**, 자료는 **성경해석 지침의 1~3순위 전부**, Claude API 키는 **아직 없음**.
2. 처음에는 카카오톡 챗봇으로 골랐으나 **「카카오톡 챗봇 서버 아닌데 웹뷰 형식으로 할 건데」**로 바로잡음 → 카카오 코드를 지우고 웹 채팅 화면으로 바꿈.
3. 프로토타입은 **개인 AWS 서버(무료) + 개인 Claude Code(구독)**로 답하게 하고 싶다. 「되는지 안 되는지만」 조사하라고 함.
4. 웹뷰는 **안드로이드·아이폰 둘 다** 되어야 함. 앱 껍데기를 지금 만들지는 정하지 않음(권한 것은 먼저 「홈 화면에 추가」, 앱은 나중).
5. 이 세션은 폐기. 나중에 이어서 작업.

## 만든 것 (커밋 5f0c84e → 6ebfec0, main)
- 파인튜닝이 아니라 **질문마다 저장소 자료를 찾아 읽고 답하는 방식**. 규칙은 코드에 옮겨 적지 않고 `docs/policy/성경해석_지침.md`·`docs/doctrine/00_교리_총정리.md`·`memory-bank/이단_판정/`을 그대로 읽는다.
- 답하는 방식 세 가지(`CHATBOT_BACKEND`): `claude-code`(개인 구독, `claude -p`를 읽기 전용 도구로 실행 — 본인 시험용) · `api`(Claude API 키) · `search`(AI 없이 강의 대목과 링크만).
- 화면 `chatbot/web/index.html` 한 장, 서버 `chatbot/src/server.mjs`(`GET /`, `POST /api/chat`), 인증 번호·하루 질문 수 제한.

## 확인 못 한 것
- **AWS 서버에서 뜨는지.** Claude Code 공식 요구 사양은 메모리 4GB 이상, 무료 t3.micro는 1GB. 2025-07-15 이후 만든 AWS 계정은 크레딧 방식이라 더 큰 서버도 크레딧으로 쓸 수 있다고 하나 블로그 출처라 콘솔에서 확인 필요. **사용자의 AWS 계정 생성 시기를 아직 못 들음.**
- **성경 본문 조회**(`tools/kjv.mjs`): 클라우드 세션에서 kingjamesbiblekorea.com이 403이라 챗봇이 장절만 적음. 접속이 열린 서버에서 본문이 들어가는지 미확인.
- **`api` 방식**: 키가 없어 가짜 응답으로만 검사.

## 꼭 기억할 제약
- **개인 구독(`claude-code` 방식)으로 성도들 질문에 답하게 하면 Anthropic 약관 위반**(구독 계정으로 다른 사용자의 요청을 대신 처리 금지 — https://code.claude.com/docs/en/legal-and-compliance). 본인 혼자 시험할 때만 쓴다. 성도들에게 열 때는 `CHATBOT_BACKEND=api`.
- 강의·교재 저작권은 교회에 있음 — 성도들에게 나누기 전에 교회 허락.
- 열기 전에 자주 나올 질문 20~30개로 답 검수.
