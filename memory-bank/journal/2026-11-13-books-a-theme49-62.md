## 재료 받는 방법(저장소 밖 스크래치 도구)
- yt-dlp는 이 PC에서 초당 약 230KB라 1080p 받기가 비현실적 → Edge headless + CDP(원격 디버깅 9337)로 유튜브 페이지의 video를 canvas에 그려 1080p JPEG를 저장(`yt.mjs`).
- 자막: 플레이어가 받는 timedtext(json3)를 가로챔(`caps.mjs`), 자동 생성 자막은 같은 서명 주소에 kind=asr(`caps_asr.mjs`).
- 2초 간격 192×108 회색 썸네일로 훑기(`yt.mjs scan`) → 슬라이드 구간(`seg.mjs`) → 구간마다 강사가 글을 덜 가리는 후보 중 화소별 중앙값에 가까운 프레임(`pick.mjs`) → 1080p 받기(`yt.mjs multi`) → 최종 `final.mjs … NN=sMM:full`.
- 여러 영상을 동시에 훑으면 대역폭이 막혀 크게 느려짐 — 한 편씩 차례로(편당 3~6분).
- 빌드는 임시 원본(1~NN-1 자리 표시 + 이 책)에서: `buildbook.sh <폴더> <NN>` — 다섯 세션이 동시에 번호를 채우는 중이라 저장소 원본 폴더 그대로는 번호가 끊겨 parse가 멈춘다.

## 그림 기준이 두 번 바뀜(2026-11-13~14)
- 11-13 「전체 화면」 → 11-14 사용자 「테두리를 잘라내고 이 내용 스크린샷만 팽팽하게」「사람 지우고 보정」「좌우 대칭」「비율 정확하게」「전수 조사」(지침 §0 bd13036, `tools/screen_crop.mjs`).
- 무대 카메라(49~58권 영상 공통)의 스크린 네 모서리 = 390,63 / 1915,63 / 1915,947 / 390,947. 편집 화면(슬라이드 원본 1920×1080)과 구분선 위치를 비교하니 카메라가 가로를 약 3% 눌러 찍어, 이 모서리를 16:9로 펴면 원래 비율이 된다(메인 세션 지적으로 1920×1108 → 1080으로 고침).
